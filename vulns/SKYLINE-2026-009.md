## Description

The rebuild stores header-name lengths in a uint16 field: a header whose name is `TrackingID` followed by 65,536 filler bytes (65,546 total; 65546 mod 65536 = 10 = `len("TrackingID")`) is stored, looked up, stripped, and serialized under the **truncated view** — on the E→C→backend wire the header *is* literally `TrackingID`. Proven end-to-end across four independent logs (E network_log, C network_log, C syslog, backend structured log) plus an internet-visible response echo: the attacker-chosen value is stamped as a legitimate `TrackingID` — Cisco TAC's cross-box correlation key — on authentication-success entries on **both boxes**, and even on rejected transactions (403-class). Pre-auth: 64KB alias headers are accepted within the 128KB `request_header_max_size`, a per-request heap cost.

**Honest scope (published as tested):** the truncation is *internally consistent* — lookups, `rm-header` strips, and serialization all use the truncated view — so the strip defenses hold: client-supplied `X-Forwarded-For` and `X-Client-Cert-Info` aliases are stripped; **no XFF, client-ID, or certificate-info spoofing was achieved** on this deployment (backend `generate_client_id()` saw the real client IP on every transaction). What remains: (1) forensic/correlation poisoning — the attacker controls the correlation ID under which their own activity is logged across both appliances, degrading TAC-side incident reconstruction; (2) parser differential — any stricter frontend (WAF/LB chaining) or raw-parsing backend sees a 65,546-char name where ATS sees `TrackingID`; (3) resource cost of 64KB-class header fields pre-auth.

Confirmed live pre-auth on Expressway X15.5.1, 2026-09-17: 5/5 alias probes returned 200 with echoed attacker-chosen TrackingIDs; zero fail2ban ticks.

## Affected Code

Header-name length storage/serialization truncates mod 2¹⁶ with no rejection of over-length names. Upstream fix `8a7a963a29` rejects names exceeding UINT16_MAX at parse time.

## Fix

1. Ship upstream `8a7a963a29` in the next rebuild; reject over-length header names with 400.
2. Until patched: alert on header names > 8KB at any frontend (False;Relay mitigations.md §1.4) — legitimate traffic never approaches this.
3. Treat `TrackingID` values in logs as attacker-influenceable when reconstructing incidents on unpatched builds; corroborate with source IP and timestamps only.
