## Description

Tomcat's `RemoteIpValve` is configured without an `internalProxies` restriction. HAProxy forwards client-supplied `X-Forwarded-For` headers without stripping them. An unauthenticated attacker sends `X-Forwarded-For: 127.0.0.1` to cause `RemoteIpValve` to overwrite `request.getRemoteAddr()`, bypassing the `RemoteAddrValve` localhost-only restriction on the Tomcat Manager application.

## Affected Configuration

```xml
<Valve className="org.apache.catalina.valves.RemoteIpValve"
       remoteIpHeader="x-forwarded-for"/>
```

Missing: `internalProxies="127\.0\.0\.1"` (or equivalent trusted proxy list).

## Fix

Add `internalProxies` to restrict which source IPs are trusted to supply `X-Forwarded-For`:

```xml
<Valve className="org.apache.catalina.valves.RemoteIpValve"
       remoteIpHeader="x-forwarded-for"
       internalProxies="127\.0\.0\.1"/>
```
