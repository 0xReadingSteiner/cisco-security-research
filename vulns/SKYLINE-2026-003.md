## Description

CUCM 15.x contains multiple independent privilege escalation paths in the sudoers configuration:

### Path A: GDB with attacker-controlled command file

```
tomcat ALL=(root) NOPASSWD: /usr/bin/gdb -pid * --command=/tmp/gdb_file
```

`/tmp` is world-writable. An attacker writes a GDB command script containing `shell <command>` which executes as root.

### Path B: Unrestricted systemctl (5 users)

```
tomcat   ALL=(root) NOPASSWD: /usr/bin/systemctl
database ALL=(root) NOPASSWD: /usr/bin/systemctl
ccmservice ALL=(root) NOPASSWD: /usr/bin/systemctl
ctftp    ALL=(root) NOPASSWD: /usr/bin/systemctl
admin    ALL=(root) NOPASSWD: /usr/bin/systemctl
```

No subcommand restriction. A malicious `.service` file achieves root execution.

### Path C: Environment variable injection

```
Defaults env_keep += "PYTHONPATH"
Defaults env_keep += "LD_LIBRARY_PATH"
Defaults env_keep += "LD_PRELOAD"
```

`PYTHONPATH`, `LD_LIBRARY_PATH`, and `LD_PRELOAD` are preserved through sudo, enabling module/library injection into any sudo-executed binary.

## Fix

- Restrict GDB sudoers entry to a fixed command file path not in a world-writable directory
- Restrict `systemctl` to specific subcommands and service names
- Remove `PYTHONPATH`, `LD_LIBRARY_PATH`, and `LD_PRELOAD` from `env_keep`
