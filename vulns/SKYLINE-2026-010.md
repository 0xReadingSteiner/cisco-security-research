# SKYLINE-2026-010 — Squathack: Pre-Auth Component-Name Claim on the Externally Bound XCP Bus (:7400)

| Field | Value |
|-------|-------|
| **ID** | SKYLINE-2026-010 |
| **CVE** | Pending (MITRE CNA of Last Resort) |
| **CWE** | CWE-306 — Missing Authentication for Critical Function |
| **CVSSv3.1** | 5.3 (Medium) — component rating; composes to 8.2 in the Null;Tone chain |
| **Vector** | AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N |
| **Product** | Cisco Expressway-C / Expressway-E X15.5.1 |
| **Component** | jabberd/XCP router, component-accept listener TCP :7400 (XEP-114 name table) |
| **Attack Type** | Remote, pre-authentication |
| **Used In** | Null;Tone (Drop 05) |

## Description

Opening an XMPP component-accept stream with `to=NAME` claims NAME in the router's
name table for the connection's lifetime, with **zero credentials evaluated before the
claim**. Rival streams presenting the same name receive an instant
`<stream:error><conflict/>` — including legitimate internal components attempting
(re)registration during a restart window. Live pre-flight on two production-version
appliances (C and E) accepted **10/10 arbitrary names**, including names absent from
the appliance's own component registry: unregistered `to=` values still open streams
pre-handshake (dynamic component auto-registration path evaluates them), so the
attacker needs no deployment knowledge. The claim releases on stream end. The port is
externally bound by default on both box roles and is watched by **no** fail2ban jail
(jails cover 22, 80/443, 5060–5062, 5222, 8443, 2222 — not 7400).

## Affected Configuration

Stock X15.5.1, MRA services enabled; :7400 bound to the appliance's external
interface(s); no ACL in front. (In-process components mean the listener has zero
legitimate external peers — pure attack surface.)

## Fix

Authenticate (or at minimum loopback-restrict) name claims on the component-accept
listener; bind :7400 to loopback given in-process components; add intrusion-prevention
coverage for the port.
